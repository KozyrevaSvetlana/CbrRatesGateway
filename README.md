# CBR Rates Gateway

Шлюз на .NET 8 Web API, через который внутренние системы получают курсы валют Банка России.

```
GET /api/v1/currency-rates?date=2026-09-25&code=USD
```

| Параметр | Обязательный | Описание |
|---|---|---|
| `date` | нет | Дата курса `yyyy-MM-dd`, с 1992-07-01 по завтрашний день (МСК). Если не передана — текущая дата по Москве |
| `code` | нет | Буквенный код ISO 4217 (`USD`, `eur`…). Если не передан — все валюты |

| Код | Когда |
|---|---|
| 200 | JSON с курсами |
| 204 | Запрошенной валюты нет в курсах ЦБ на эту дату |
| 400 | Некорректная дата/код или дата вне диапазона (ValidationProblemDetails) |
| 502 | Сайт ЦБ недоступен или вернул некорректный ответ (ProblemDetails) |

Пример ответа:

```json
{
  "requestedDate": "2026-09-25",
  "ratesDate": "2026-09-25",
  "source": "cbr.ru",
  "rates": [
    { "id": "R01235", "numCode": "840", "charCode": "USD", "nominal": 1,
      "name": "Доллар США", "value": 83.5211, "unitRate": 83.5211 }
  ]
}
```

## Выбор сервиса ЦБ

У ЦБ есть три варианта получения курсов:

1. **`XML_daily.asp?date_req=dd/MM/yyyy`** — лёгкий XML, одним GET-запросом возвращает курсы **всех** валют на дату.
2. SOAP-сервис `DailyInfoWebServ/DailyInfo.asmx` (`GetCursOnDate`) — те же данные, но с SOAP-обёрткой, WSDL и более тяжёлым ответом.
3. `XML_dynamic.asp` — динамика одной валюты за период (нужен внутренний ID `R01235`, а не ISO-код).

Выбран **XML_daily.asp**: это официальный сервис, один запрос покрывает оба сценария (одна валюта и все валюты), а ответ хорошо кэшируется по ключу «дата → все курсы». Фильтр по коду выполняется уже у нас, поэтому запросы по разным валютам на одну дату идут в ЦБ один раз.

Особенности, которые учтены: ответ приходит в `windows-1251` (регистрируется `CodePagesEncodingProvider`), десятичный разделитель — запятая, курс указан за `Nominal` единиц (дополнительно отдаём `unitRate`), на выходные ЦБ возвращает последний установленный курс (поэтому в ответе есть и `requestedDate`, и `ratesDate`).

## Кэш (Redis)

* Ключ: `cbr-gateway:rates:{yyyy-MM-dd}`, значение — JSON со всеми курсами на дату.
* TTL: курсы на прошедшую/текущую дату окончательны — `FinalRatesTtl` (7 дней). Если запрошена будущая дата, а ЦБ ещё не опубликовал курс — `PendingRatesTtl` (15 минут), чтобы подхватить публикацию.
* Redis недоступен — сервис продолжает работать напрямую с ЦБ (ошибка логируется).
* Если строка подключения `ConnectionStrings:Redis` пустая (так по умолчанию в `appsettings.json`) — используется in-memory кэш и в лог пишется предупреждение. В контейнере задаётся переменной `ConnectionStrings__Redis`.
* Пустой ответ ЦБ не кэшируется: это может быть временный сбой на их стороне.
* Одновременные запросы за одну дату при пустом кэше объединяются (`RatesRequestCoalescer`): в ЦБ уходит один запрос, остальные ждут его результат.

Вызовы ЦБ идут через `HttpClientFactory` со стандартным resilience-пайплайном (retry, timeout, circuit breaker).

## Структура

```
src/CbrRatesGateway.Api/        Web API
  Controllers/                  HTTP-контракт, валидация
  Services/                     клиент ЦБ, парсер XML, кэш, бизнес-логика
tests/CbrRatesGateway.Tests/    xUnit + Moq: парсер, клиент, кэш, сервис, контроллер, интеграционные тесты API
openapi/cbr-rates-gateway.yaml  спецификация OpenAPI 3.0
Dockerfile, docker-compose.yml  контейнеризация
Jenkinsfile                     CI: restore → build → test → docker build → push
```

## Запуск

```bash
dotnet test                         # тесты (внешние зависимости не нужны)
docker compose up --build           # API + Redis, Swagger: http://localhost:8080/swagger
curl "http://localhost:8080/api/v1/currency-rates?code=USD"
```

## Асинхронный вариант

Получение курсов с сайта ЦБ стоит вынести из пути запроса в фоновый воркер (`BackgroundService`/Quartz): он по расписанию — после публикации курсов ЦБ на следующий день (~15:30 МСК рабочих дней) — загружает их и складывает в Redis/БД, а API отдаёт данные только из хранилища и не зависит от доступности cbr.ru. Для дат, которых нет в хранилище, API ставит задачу в очередь (RabbitMQ/Kafka) и отвечает `202 Accepted` со ссылкой на статус (или клиент получает результат через callback/топик), а о публикации новых курсов воркер уведомляет подписчиков событием `CurrencyRatesPublished` — тогда внутренним системам не нужно опрашивать шлюз.
